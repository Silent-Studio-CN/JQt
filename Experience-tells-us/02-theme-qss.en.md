# 02 · Theme Rendering and QSS

> The theme system of JQt: official setTheme(path, vars) template rendering + community-defined dual themes.
> This chapter documents all the experiences regarding template mechanisms, style priorities, and residual issues.

## fluent.qss.tpl template rendering mechanism

- The official template is available **22 %var% placeholders**(win-bg/fg/accent/btn-*/card-*/input-*/nav-*...) .
- Rendering method: Read the template → `replace("%"+key+"%", value)` - `app.setStyleSheet(qss)`.
- **"render based**The file path lookup does not rely on setTheme, and the exe packaged version is safe.
- Template reading priority: File system themes/fluent.qss.tpl takes priority, with resources within the jar as a safety net.
- The commonly used three-segment splicing in the community version: fluent.qss.tpl (basic) + qraft-styles.qss (three-dimensional button) + sck-extra.qss (exclusive control).

## 2. Style Priority (The Most Common pitfall in this Directory

Priority from high to low:
1. **Control-level setStyleSheet**(`widget.setStyleSheet(...)`The highest, always covering the entire situation
2. **Object name selector**(`QPushButton#themeBtn`"Second highest.
3. **App-level/Win-level setStyleSheet** -- Global

### Pitfall 1: The theme is pinned by a dark overlay at the control level
```java
// 错误示范：启动时对每个控件单独 setStyleSheet 暗色
applyDarkStyles();   // 每个控件 setStyleSheet 暗色
// 之后无论怎么切全局主题，控件级样式优先级更高 → 永远暗色
```
**"Repair**Delete the batch overwriting at the control level and hand over all to the global QSS template rendering.
When individual controls require special styles, use the objectName selector to put them into the template.

### Pitfall 2: Inline style hard-coded color (black residue)
```java
topBar.setStyleSheet("QFrame#topBar { background-color: #1f1f1f; }");  // 硬编码
```
The inline style has the highest priority, and the template rendering cannot cover it → Even after cutting to a light color, the top bar is still black.
**"Repair**Remove the inline style and change it to template rules + variables`%topbar-bg%`"

### Pitfall 3: Hard-coded dark colors in QSS files
```css
QTextEdit, QPlainTextEdit { background: #1a1a1a; }   // 日志区永远黑
```
**"Repair**: Quantification -- `%terminal-bg%` / `%terminal-fg%`A light-colored confession with dark characters on the background
Dark watches maintain a black background at the terminal.

## 3. Dual-theme design (Light color/dark color variation table)

- Two isomorphic variable tables:`lightVars()` / `darkVars()`The key sets must be exactly the same.
Otherwise, the residual %var% after rendering of a certain topic will cause the QSS parsing to fail.
- **Design token**Unified input variable table: border/border-deep/radius/card-radius/pill-radius/fontsize.
- accent dynamic variable: Generated by lighten/darken/withAlpha when switching the theme color
accent: hover/pressed/deep/ ghosthover/ghostpressed.
- **applyTheme(name) must actually use the name parameter**-- Historically, there have been instances of overly hard coding dark colors
The version of QSS that completely ignores parameters (the biggest culprit for the ineffectiveness of cutting light colors).

## 4. Troubleshooting for failed QSS parsing

- Qt Report `Could not parse application stylesheet` Time:
1. Check if there is any rendering result**Unreplaced %var%**"Regular expression `%[a-z-]+%` "Scan;"
2. Check the color format (mix rgba() with #RRGGBB);
3. Check the selector syntax`QLabel#detailPanel QLabel` This combination of offspring and ID.
- The literal %var% in the template comments (such as the description of "filled by setTheme()") is harmless and can be ignored.

## 5. Theme button interaction design

- The theme switch button icon should display "Where to Go after clicking" : Dark mode display ☀ (Click it to go back to light),
Light mode shows ☾ (click it to dark).
- After switching, update the button text synchronously; otherwise, the user will not know the current status.

## 6. Verify the methodology

- **Rendering probe**Directly invoke the renderThemeQss + variable table to assert whether the output includes or excludes the key color values:
`LIGHT has #f3f3f3: true`,`LIGHT terminal dark: false`.
- **Operation log**:`[SCK] theme=fluent-light qss len=11085`There are no parse errors in stderr.
- Note: Both the foreground text color (color:) and the background color (background:) need to be checked.
When searching for "residual color value", first confirm whether it is fg or bg.
