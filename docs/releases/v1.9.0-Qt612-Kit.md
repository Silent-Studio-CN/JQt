## 预告:加快追赶 QtJ(QtJambi)

Qt 6.12.0 这一版解决的是**"跟上版本"**;下一阶段目标转为**"补齐广度"**,正面追赶 QtJambi:

| 方向 | 计划 |
|---|---|
| **覆盖对齐** | 以 Qt 6.12 的类清单为基线,逐模块核对 JQt 与 QtJambi 的差距,公开**可核对的覆盖率表** |
| **缺口模块** | 优先补当前 intentionally-absent 的项:对象系统通道(dock / QMovie / QPicture 等)、QML/Quick、多媒体方向 |
| **版本节奏** | 跟随 Qt 每半年一个版本线:**LTS 线出正式版,非 LTS 线出预览版**;CI 矩阵保持"最新 + LTS"双线 |
| **自动化优先** | 新增 API 尽量走生成器(`tools/jqt-gen`)+ 金标准测试并入,少手写 JNI 桥,降低回归面 |
| **可比性** | 每个版本附**"相对 QtJambi 的覆盖率与差异清单"**,可外部复核、可复现 |

**量化目标**:在 Qt 6.12 → 6.14 周期内,把与 QtJambi 的 API 覆盖差距收敛到**可量化的小范围**,
并在每个版本发布时给出当期的覆盖率数字(而不是只给"支持了哪些类")。

> 说明:JQt 不追求与 QtJambi 二进制/API 逐字兼容 —— 目标是**能覆盖同样的 Qt 能力面**,
> 同时保留 JQt 的取舍(纯 Java 值对象、显式所有权 + Cleaner、可生成、无隐藏全局状态)。

## 兼容性

- **源码兼容**:从 1.8.0 升级无需改代码(API 未删减,仅新增 Qt 版本支持)
- **运行期**:同一份 jar 可分别配 6.12.0 / 6.8.3 的裸库运行
- **工具链**:MinGW-w64 13.1.0(与 Qt 6.12.0 官方 SDK 一致)

## 已知事项

- macOS/Linux/Windows 的 6.12.0 均走**手动 7z** 安装。经复核(J12):aqtinstall 3.3 **可以**解析 Qt 6.12.0
  的元数据,**真正的原因是清华镜像当时没有同步 6.12.0 的 `Updates.xml`/`.sha256`**
  (`Failed to download checksum ... Updates.xml`);另外 Qt 新仓库把版本元数据放在**架构子目录**
  (`qt6_6120/qt6_6120_mingw/Updates.xml`),aqt 按旧路径取也会落空。CI 因此改用多镜像回退 + 直下 7z,
  比依赖 aqt 更稳。
- Maven Central 仍未发布 1.8.0/1.9.0 线(当前 Central 为 0.7.5),JitPack 按 tag 构建
